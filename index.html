Trunk-Based Development

Integrate small changes into a single shared branch, often.

What is it?

Trunk-Based Development (TBD) is a branching model where every developer integrates their work into one shared branch, the trunk (usually main), at least once a day. Feature branches, when used, are short-lived (hours, at most a couple of days) and merged back quickly through a fast code review and an automated CI pipeline.

How it looks

Trunk commits (always releasable) Short-lived branches (hours to ~2 days) Release tag / branch (hotfixes only)

Core practices

  • Small, frequent commits keep merges trivial.
  • Continuous Integration: every push is built and tested automatically.
  • Fix a broken trunk immediately; it is the team's top priority.
  • Feature flags hide unfinished work so it can ship safely.
  • Release from trunk by tagging; cut release branches only when needed for hotfixes.
